# 保留 Raw Frame，Reading 與 Sleep Session 由其衍生

戒指協定是逆向而來，解析很可能出錯，而且戒指在 Sync 後會清除自己的資料，錯過就無法重抓。所以每次 Sync 收到的 Raw Frame 一律完整保存，Reading 與 Sleep Session 都只是它的衍生資料，可以隨時清除並依最新解析器重建。

同步的順序因此固定為：Raw Frame 寫入資料庫並確認成功之後，才對戒指送出清除命令。

## 考慮過的替代方案

- 只存解析後的值：資料庫較小，但解析錯誤無法補救，等同永久遺失健康資料。
- 以覆蓋方式修正：無法處理「解析規則整個改變」的情況。

## 後果

- 資料庫體積較大，這是個人用途，可以接受。
- 必須維護「重建」功能，並保證重建是冪等的。
